## 失败归因与后续优先级

1. **复现集合混入错误的辅助断言。** Seaborn 的原探针依赖不存在的私有属性，scikit-learn 的原集合误断言了内部配置；这些内容随原定义被冻结，之后 Agent 虽改正脚本并修对实现，原探针仍不能通过。下一步应把 Issue 的最小公开复现与辅助诊断分开，并校验修改前的失败确实来自要修的行为。
2. **测试范围与环境约束不一致。** Astropy-13579 第一次扩展到其他天文模块，受到过期 IERS 数据及禁网条件影响，原 probe 也未闭环；独立的受影响模块验证则通过。后续应先完成相关模块验证，再记录范围更广的环境失败，而非用无关失败替代缺陷验收。
3. **修复遗漏公开契约或边界。** Pylint 两次都未满足 `--duplicates=0` 的 CLI 行为，Seaborn 第一次及 Astropy-13977 第一次也未通过独立测试。仅让流程合规不会提高这些候选的正确性；还需要完整断言 stdout、异常、空形状及类型协议等行为。

本轮没有与普通单 Agent 做同配置配对，不能把与历史比例的差异全部归因于自动复验。六道题两次都修对，也不能解释为整个题库的稳定正确率。后续改动应重新冻结并独立评测，不把本轮已见的失败结果用于当前运行补考后再改写成功率。

## 判分口径

**解题正确率**：候选生产补丁通过文件级独立 verifier 的次数 / 有效环境下已完成的模型次数。

**工作流合规率**：机器证据满足修改前失败、修改后同一 reproducer 通过、最后编辑后测试通过等任务契约的次数 / 同一分母。

**端到端成功率**：独立 verifier 通过、工作流合规、正常 `final` 收尾且无执行错误的次数 / 同一分母。与前端、队列、审批、GitHub 发布链路的系统验收分开。

逐题还报告「两次都修对」与「至少一次修对」，避免把同一道题的两次重复当作两道独立题。所有完整模型失败保留；供应商额度/限流中断单列并保留原始轨迹，不悄悄算作算法失败或删去。

这里不是官方 SWE-bench harness 的 resolved 指标。18 次小样本重复的观测比例，即使超过 90%，也不足以证明所有真实缺陷上的总体正确率或成功率稳定超过 90%。

## refs 故障与环境复校

Matplotlib、Seaborn、Flask、Sphinx 的 bare 仓库缓存缺少 `refs` 目录。原提交对象和 `packed-refs` 仍存在；补齐 `refs/heads` 与 `refs/tags` 后，四个缓存均经 `rev-parse --is-bare-repository` 和 `cat-file -e <base_commit>^{commit}` 验证，未修改既有提交或引用文件。首次校准错误保留在原批次报告，补跑使用独立报告。

Matplotlib 复校时，原始代码及参考修复都在收集测试时尝试创建 `/testbed/result_images/test_widgets`，被只读挂载阻止。它未进入模型阶段，不能作为 Agent 修复失败，也不能把这次环境校准算作一次模型成功。
