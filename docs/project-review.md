## 本轮修复

| 问题 | 实际后果 | 修复与验证 |
|---|---|---|
| 重试只改队列 attempts，tasks.failed 不可再次领取 | 第二次根本没有调用 Agent | 重试领取允许 failed；测试明确断言 Agent 实际被执行两次 |
| API 启动统一重置运行任务 | 重启 API 会破坏独立 Worker 的状态 | 仅 inline 标记中断；API 重启与非法 execute/resume 集成测试 |
| 队列 resume 的 SSE 看到 interrupted 就结束 | Worker 尚未领取，客户端已断流 | 排队/领取期间继续观察；测试覆盖等待后收到 final |
| Worker 与 API 的 RAG 决策不同 | 相同配置在两种部署方式中执行不同策略 | 提取共享策略，并验证工具权限一致 |
| 检查点按消息数生硬裁剪 | 丢失系统要求、原始问题，出现孤立 tool result | 保留任务锚点、完整回合裁剪、加载时验证配对 |
| initial_messages 每次运行都复用 | 多角色返工可能忽略新的失败反馈 | 快照只消费一次，并追加本次任务输入；两次运行回归测试 |
| --once 不续租、不处理取消；退出等待停止心跳 | 长任务过期，退出期间失去持有权 | --once 轮询心跳/取消，SIGTERM 支持，等待期间继续续租 |
| 过期租约只回收队列，不处理 tasks.running | 回收后任务无法执行，且旧 Worker 可能仍活着 | SQLite 事务隔离为 dead，并标记 interrupted；确认旧 Worker 停止后显式恢复 |
| 旧 Worker 可覆盖新队列状态；取消先删租约 | 状态错写、活动任务失去租约 | 结算校验 claimed 状态和 owner；取消先改任务状态，只删除 queued 项 |
| Redis 扫描包含其 ZSET 索引 | 对索引调用 HGET 会 WRONGTYPE | 跳过索引键；不把这个修补描述为 Redis 生产验收 |

SQLite 的过期隔离是有意收紧语义：租约失效不证明旧进程已停止。尚无执行 fencing，因此不承诺自动切换或副作用恰好执行一次。用户确认旧进程与其工具停止后，才能恢复。

## 尚未达到优秀的方面及下一轮验收标准

| 维度 | 未解决的问题 | 可检验的完成标准 |
|---|---|---|
| 实验可信度 | 开发题复用、9/20 校准未过、自研 verifier 与官方 harness 不同 | 固定策略与判分，新的未调参实例，重复配对，逐条持久化校准和失败；按题聚合置信区间 |
| 运行可靠性 | 无执行 fencing、仓库互斥、背压；工具可能重放 | 两 Worker 并发与崩溃注入不重复写；单仓库冲突任务受控；取消/超时有可验证收口 |
| 部署安全 | 无鉴权、仓库授权、租户隔离 | 未授权调用不能修改仓库；路径授权与配额测试通过 |
| 多机部署 | Redis 非原子，业务状态仍为 SQLite | 统一状态存储、原子队列、远端工作区可达，并通过真实重启/网络异常演练 |
| 模型策略价值 | 动态 RAG / 探针无独立消融 | 同模型同题配对对照，公开成功率、Token、用户完整等待时间和失败案例 |

| 可复现性 | 大部分原始报告仅本机保存，模型/镜像可能漂移 | 提交可脱敏分享的报告、补丁、配置、镜像 digest 与重放说明 |

改进应按这些验收标准推进，不靠继续堆功能或漂亮图表判断完成。简历可写“实现并评测四种执行策略，真实 20 题抽样中 11 题进入模型阶段、33 次运行 21 次通过，识别 RAG 无收益与任务恢复缺陷”；不要写“无污染集 57.1%、显著优于基线、生产级自动故障切换”。
