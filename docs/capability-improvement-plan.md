## 2. 优秀工作的做法（只列有消融或官方说明的部分）

| 工作 | 做法 | 证据 |
|---|---|---|
| SWE-agent（NeurIPS 2024） | 专用编辑命令，编辑后回显并拒绝有 lint 错误的编辑；搜索结果汇总展示；100 行查看窗口；只保留最近 5 条观测 | GPT-4 Turbo、Lite 300 题：完整配置 18.0%；有编辑命令但无 lint 15.0%；无编辑命令 10.3%；保留全部历史 15.0% |

| Anthropic SWE-bench 脚手架（2024-10） | 只有 bash 和编辑两个工具；提示词：探索 → 写复现脚本并运行 → 修改 → 重跑复现 → 考虑边界情况；运行到模型认为完成或上下文用尽 | Claude 3.5 Sonnet 在 Verified 上 49%；官方说明，没有组件级消融 |
| mini-SWE-agent | 约 100 行代码，只有 bash，线性历史 | 强模型下 Verified 超过 74%。说明模型强时脚手架可以很简单，但这个分数依赖前沿模型 |

## 3. 本轮实际改动（`single_enhanced` 变体，基线逐字不变）

1. `code_outline`：AST 骨架加按符号精确取源码（参考 AutoCodeRover），做了路径校验。
2. 编辑语法守卫：编辑会引入语法错误时拒绝写入，返回行号上下文（参考 SWE-agent 的 lint 编辑）。
3. 提示词追加：先看已有测试和同类实现，遵循仓库约定；逐项列出迭代器探针；修复后考虑边界情况（参考 Anthropic 的提示词）。

上一版草案里的 `analyze_repository`、`analyze_code_semantics` 已删除：前者有命令注入风险，
而且和 `search_code` 功能重复；后者没做路径校验，而且号称「类型推断」实际做不到。

## 4. 验证方法

- 计划样本：SWE-bench Verified test split，种子 `20261004` 按仓库分层，12 个仓库各抽 1 题。实际完成配对运行并进入 `verified_ab_summary.csv` 的是 7 题；不得把计划抽样数当成已完成数
- 配对：同一题依次运行 `single_no_rag` 与 `single_enhanced`，各重复 2 次；模型、轮数上限（14）、上下文配置不变
- 判分：先用自研 verifier，再导出预测，用官方 harness 复核
- 局限：计划的 12 题按仓库各取 1 题，但实际完成配对的只有 7 题；这一分布与 Verified 全集（django 占 46%）不同，样本量不足以下显著性结论；模型可能见过这些公开题目（数据污染）

## 5. 已落地：动态策略路由

静态的 `single_enhanced` 不再作为所有任务的默认增强方案。`backend/src/agents/strategy.py` 现在根据仓库与问题特征生成 `AgentStrategy`：

1. 只对 Python 主导且文件/仓库达到阈值的任务暴露 `code_outline`。
2. 只对行为语义问题追加强制探针；纯文档、格式与配置任务不施压。
3. API、Worker 和 `single_adaptive` 真实评测变体共用同一决策函数；报告保存理由与原始指标。
4. 关闭路由器会回到历史提示词和工具集，保留既有实验的可复现性。

7 个已完成 Verified 配对实例的离线决策 smoke 产生 2 个 `outline_only`、1 个 `probe_only` 和 4 个 `standard`。该结果只验证决策分支，尚不是端到端收益证据。

## 6. 还没做、按收益排序的方向

1. **多补丁采样 + 测试选择**（Agentless 证据最强，+6.3 个百分点）：每题生成 N 个候选补丁，用回归测试和 Agent 自己写的复现测试筛选，再多数投票。成本约为 N 倍 Token。
2. **复现测试前置**：把 `protocol_probe` 升级成「先写复现脚本并确认在原代码上失败」的硬性步骤，同时为方向 1 提供筛选依据。
3. **轮数预算**：Anthropic 的做法不设固定轮数。我们的 14 轮上限和第 9 轮强制编辑可能过紧；需要在新题上配对比较 14 轮和 30 轮，同时统计 Token 成本。
4. 观测窗口与历史压缩参数，参照 SWE-agent 的消融结果做对照。
